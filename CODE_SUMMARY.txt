一、项目目标
============================================================

该项目使用 Habitat-Sim 0.3.3 和 ReplicaCAD 生成多机器人世界状态数据。

每个 Level-1 状态包含：
1. 三个机器人各自的 RGB 图像。
2. 三个机器人各自的深度图。
3. 三个机器人各自的实例分割图。
4. 全局正交 BEV RGB。
5. BEV 实例分割。
6. BEV 高度图。
7. BEV 可导航 occupancy。
8. 机器人位姿、相机内外参和坐标变换。
9. 可控物体状态、AABB 和可见性。
10. 多机器人视野重叠难度。
11. RGB-D 和 BEV 几何验证记录。
12. 人工检查 contact sheet。

Level-2 数据在 Level-1 WorldState 上施加精确干预，再使用同一个 Habitat
后端重新渲染，生成 before/after 配对、结构化干预、自然语言指令和
可见性变化。

四、坐标系与几何
============================================================

文件：src/mri_dataset/coordinates.py

1. Habitat 世界坐标系
---------------------

右手坐标系：
    +Y：向上
    XZ：地面
    yaw = 0 时机器人朝向 -Z
    yaw 正方向遵循右手定则

四元数统一保存为：
    [x, y, z, w]

距离单位：
    meter

角度单位：
    radian

2. Habitat 相机坐标
-------------------

    +X：右
    +Y：上
    -Z：前

3. OpenCV 相机坐标
------------------

    +X：右
    +Y：下
    +Z：前

基变换：
    HABITAT_FROM_CV = diag(1, -1, -1, 1)

4. 主要函数
-----------

normalize_angle(yaw_rad)
    把角度归一化到 [-pi, pi)。

yaw_to_quaternion_xyzw(yaw_rad)
    把 yaw 转成 xyzw 四元数。

normalize_quaternion_xyzw(q)
    校验并归一化四元数。

quaternion_to_matrix(q)
    四元数转 3x3 旋转矩阵。

rotate_vector(q, vector)
    用四元数旋转向量。

forward_from_quaternion(q)
    将相机局部前方 [0, 0, -1] 转到世界坐标。

transform_matrix(position, quaternion)
    生成 4x4 刚体变换矩阵。

invert_transform(T)
    使用旋转转置和逆平移计算刚体逆矩阵。

camera_transforms(position, quaternion)
    同时返回：
    - T_world_from_camera_habitat
    - T_camera_habitat_from_world
    - T_world_from_camera_cv
    - T_camera_cv_from_world

camera_intrinsics(width, height, hfov, near, far)
    计算 fx、fy、cx、cy 和 K。

backproject_depth(depth, intrinsics)
    将 pinhole Z-depth 反投影到 OpenCV 相机坐标。

transform_points(T, points)
    对点集应用 4x4 变换。

project_world_points(...)
    将世界点投影到目标相机像素。

reproject_between_cameras(...)
    从源深度反投影到世界，再投影到目标相机。

六、机器人和相机采样
============================================================

文件：src/mri_dataset/sampling.py

_valid_position(...)
    检查：
    - 坐标有限
    - 位于 navmesh
    - 楼层高度满足 tolerance
    - 距障碍物满足最小距离

sample_robot_positions(...)
    1. 随机生成第一个机器人 anchor。
    2. 读取 anchor 所在 navmesh island。
    3. 在 anchor 周围 local_sampling_radius_m 内生成其他机器人。
    4. 所有机器人必须属于同一 island 和同一楼层。
    5. 检查机器人之间的最小距离。
    6. 最多重试 max_tries 次。

sample_yaws(...)
    random：
        每个机器人独立随机 yaw。
    shared_region：
        所有机器人基本看向同一个局部区域，并加入角度抖动。
    mixed：
        65% 使用 shared_region，35% 使用 random。

build_robot_states(...)
    为每个位置构建 RobotState，随机采样相机高度，分配红/绿/蓝 proxy
    和 1001/1002/1003 semantic ID。


七、受控物体
============================================================

文件：src/mri_dataset/objects.py

handles_by_suffix(template_manager, suffixes)
    使用文件名后缀在 Habitat 模板库中解析唯一 handle。
    匹配不到或匹配多个都会报错。

list_template_records(template_manager)
    列出 handle、render asset、collision asset、semantic ID 和 scale。

aabb_dict(aabb, transform)
    将局部 AABB 的 8 个角变换到世界坐标，再计算世界 AABB。

controlled_object_collision_free(...)
    先做快速几何检查：
    - 对象 active 状态
    - AABB 是否存在
    - 是否离开视觉场景边界
    - 是否离机器人过近
    - 是否与其他受控对象 AABB 重叠

随后 HabitatBackend.entity_collision_report(...) 会将目标实体临时设为
dynamic，只执行 Bullet 离散碰撞检测而不推进时间，从而检查墙、沙发、
桌子、柜子、静态家具、机器人 proxy、受控物体和其他刚体。机器人和物体
使用同一套检查；object_collision_report(...) 是保留类型检查的兼容包装。
仅容忍阈值内的垂直地板支撑接触。


八、BEV
============================================================

文件：src/mri_dataset/bev.py

BevMapping
----------
字段：
    x_min, x_max
    z_min, z_max
    width, height

from_bounds(...)
    根据场景世界边界和期望米/像素构造 BEV。
    宽度由 X extent 决定，高度按 X/Z 实际比例计算。

坐标约定：
    BEV u 向右 = 世界 +X
    BEV v 向下 = 世界 +Z
    图像视觉向上 = 世界 -Z

world_to_bev(x, z)
    世界坐标转浮点像素坐标。

bev_to_world(u, v)
    像素坐标转世界 X/Z。

meters_per_pixel_x / meters_per_pixel_z
    最终实际像素尺度。

habitat_orthographic_depth_to_metric(...)
    Habitat-Sim 0.3.3 在读回前会执行通用 depth unprojection，但该通用
    过程对 orthographic projection 返回 reciprocal pseudo-depth，而不是
    线性米制距离。本函数反解 depth buffer 后按 near/far 线性化；合法性
    由 finite、raw != 0、depth-buffer ∈ [0,1] 和 metric ∈ [near,far]
    共同决定，不能用 raw > 0，因为约 6.01 m 奇点之后的合法值为负。
    synthetic test 覆盖 1/2/5/8 m，真实 Habitat integration test 使用
    Bullet downward ray 作为非循环 oracle。

occupancy_from_pathfinder(...)
    调用 Habitat 的 C++ PathFinder.get_topdown_view() 一次生成 NavMesh
    栅格，再按世界 X/Z 注册到视觉 BEV bounds。后端按 scene/floor 缓存
    occupancy，不再为每个 state 执行数百万次 Python is_navigable 调用。

annotate_bev(...)
    绘制机器人位置、颜色、朝向、FOV 和相机高度。

compute_fov_overlap(...)
    用 BEV 中的几何 FOV 扇形计算：
    - 三机器人共同 IoU
    - 两两 IoU
    - easy / medium / hard

该 FOV overlap 是几何近似，不包含墙体遮挡。真实实体可见性来自
instance 图。


九、Habitat-Sim 后端
============================================================

文件：src/mri_dataset/habitat_backend.py
类：HabitatBackend

职责
----
这是唯一允许直接修改 Habitat 状态的模块。

WorldState 是状态源；Habitat 只负责：
    - 加载场景
    - 设置相机
    - 生成 proxy 和受控对象
    - 渲染传感器
    - 执行物理射线验证

初始化
------
1. 检查 scene dataset config。
2. 检查当前场景的显式 navmesh。
3. 使用独立 PathFinder 预加载 navmesh，保存 navmesh_bounds。
4. 创建无传感器 probe Simulator，读取完整 rendered scene AABB。
5. 使用 render_bev_bounds 构造视觉 BevMapping；NavMesh bounds 仅用于
   navigability 和 occupancy 注册。
6. 生成过滤后的临时 scene dataset config：
   - 删除本机未安装的可选 Fetch URDF。
   - 删除文件不存在的 navmesh 条目。
   - 原始 ReplicaCAD 配置不被修改。
   - 后端关闭时删除临时配置。
7. 按视觉 bounds 创建正式 Habitat Simulator。
8. 再次显式加载当前场景 navmesh。
9. 加载机器人 proxy 模板。
10. 解析可控物体白名单。

传感器
------
每个机器人 agent：
    RGB pinhole
    depth pinhole
    OBJECT_ID instance pinhole

额外 BEV agent：
    RGB orthographic
    depth orthographic
    OBJECT_ID instance orthographic

当前共有：
    Agent 0 = Robot 1
    Agent 1 = Robot 2
    Agent 2 = Robot 3
    Agent 3 = BEV

Habitat-Sim 0.3.3 的 orthographic scale 使用：
    1 / horizontal_world_extent

apply_world_state(state)
------------------------
1. 清除上一个状态生成的刚体。
2. 同步每个 RobotState 的相机。
3. 设置不可见 Habitat agent 的相机状态。
4. 生成可见的 kinematic 机器人 proxy。
5. 生成 active 的受控物体。
6. 校验 BEV 高度低于 scene AABB 顶部并保留 ceiling clearance。
7. 将 BEV 相机放到视觉场景中心和 floor_y + BEV height。
8. BEV 相机旋转为垂直向下。

机器人为什么分 agent 和 proxy：
    Habitat agent 只作为相机，不会自动出现在其他机器人的 RGB 中。
    proxy 是独立刚体，使机器人可见并进入实例图。

create_object_state(...)
    临时实例化模板，读取 collision AABB，将 AABB 底面对齐楼层，再构造
    ObjectState。

refresh_object_bboxes(...)
    WorldState 应用后，从 Habitat 查询权威碰撞 AABB 并转到世界坐标。

floor_surface_y(...)
    从 NavMesh 点上方向下发射物理 ray，解析真实地板表面 Y。机器人 base、
    WorldState.floor_y 和受控物体底面都使用该物理高度，而不是可能偏高的
    NavMesh polygon Y。

support_object_on_floor(...)
    在 Level-2 相对放置或 object_translate 后重新读取目标模板 collision
    AABB，并按目标 XZ 下方真实地板 Y 重建物体支撑高度，避免浮空或陷地。

entity_collision_report(...)
    应用完整 WorldState 后执行 Bullet 离散接触检测，返回碰撞对象、穿透
    深度和接触位置。支持 robot proxy 和 controlled object。目标临时设为
    dynamic，以覆盖 kinematic 与 kinematic/static 的重叠。

机器人 proxy 生成时会读取 collision AABB 的 local min Y，将真实底面对齐
RobotState 的 physical floor base；不能直接把 mesh 原点放在地板上，否则
轮子/侧刷会陷入地面。

render(state)
-------------
1. apply_world_state。
2. 刷新对象 AABB。
3. 一次读取所有 agent 观测。
4. 转换 RGB/depth/instance dtype。
5. 转换 BEV 正交深度。
6. 计算：
       height = BEV camera height - metric depth
7. 首次遇到 scene/floor 时计算并缓存 occupancy，后续 state 直接复用。
8. 用 OBJECT_ID 统计每个实体在每个机器人实例图中的可见像素。
9. 返回当前 state 的 entity_object_ids 映射供序列化。

输出：
    robots[robot_id].rgb
    robots[robot_id].depth
    robots[robot_id].instance
    bev_rgb
    bev_depth
    bev_metric_depth
    bev_instance
    height
    occupancy

validate_pinhole_depth_centers(...)
    将每个相机中心像素 Z-depth 与正前方物理射线命中距离比较。

validate_height_rays(...)
    从渲染高度接近 0 的真实地板像素采样，并只比较 Bullet ray 同样命中
    地板的点。这样避免 render mesh 与 collision-only 家具几何差异造成
    误报。最大误差必须 <= 0.02 m，否则状态不允许保存；逐射线记录写入
    state.json。

close()
    关闭 Simulator，并删除临时过滤配置。


十、Level-1 采集

    - categories.json
    - splits/
    - scenes/
    - interventions/

    扫描所有 state.json 和 edit JSON，更新 dataset.json 和 split。

    train split 中 states 只包含 factual Level-1；after_states 与

    所有 layout family 暂时都写入 train。
    val/test 为空。
    正式跨公寓实验需要按 family 实现 train/val/test 分配。

collect_level1(...)
    对每个状态：
    - state ID = state_000001 等
    - 首选 seed = random_seed + index - 1
    - 构造 WorldState
    - 对每个 robot proxy 做 Bullet collision 检查
    - 无效布局按确定性备用 seed 重采样，默认最多 100 次
    - 渲染并原子保存
    - 更新数据集索引

已有状态目录不会被覆盖。

十三、Level-2 干预
============================================================

文件：src/mri_dataset/interventions.py

Intervention
------------
字段：
    type
    target_id
    parameters

to_dict()
    序列化结构化干预。

from_dict()
    从 JSON 构造干预并检查必需字段。

canonical_instruction(...)
    生成固定英文自然语言指令。object_translate 指令显式包含位移距离、
    方向和 reference frame，与 structured intervention 信息等价。

支持类型
--------

robot_translate
    默认 target_local。
    新位置：
        old_position + forward_m * robot_forward
    修改后同步相机。

robot_rotate
    yaw += delta_yaw_rad，并归一化角度。
    不改变位置。

object_remove
    active = false。

object_place_relative
    当前支持 relation = front。
    将对象放到 reference robot 前方指定距离。
    保持物体原支撑 Y，不使用机器人底盘 Y。

object_translate
    支持参考系：
    - world
    - object_local
    - reference_robot
    同时平移对象 AABB。

apply_intervention(...)
    使用 deepcopy，不修改 before WorldState。
    设置 parent_state_id、after state ID 和 intervention。

validate_robot_translation(...)
    严格检查：
    - XZ 水平位移等于请求距离，绝对误差 <= 1e-6
    - 位移方向等于 target-local forward
    - 目标仍在 navmesh，snap 偏差 <= 1 mm
    - try_step_no_sliding 能完成完整直线路径
    - NavMesh 与 physical floor 均没有换楼层
    - 目标 Y 重新解析为 physical floor
    - 不违反机器人最小距离
    - after-state robot proxy 通过 Bullet collision

无效精确目标会被拒绝，不会缩短距离或 snap 到附近点。
