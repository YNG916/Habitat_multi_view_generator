HSSD SEMANTIC-REGION MULTI-ROBOT DATASET — CODE SUMMARY
===================================================

版本与边界
----------
Dataset schema: 3.1.0
Protocol: mri-hssd-region-formal-v2.1
WorldState schema: 0.4.0
SceneRegistry schema: 2.1.0
Preprocessing algorithm: 2.1.0-region-v7

正式运行只接受标准 hssd-hab。data/scene_datasets/hssd-hab 是指向
data/versioned_data/hssd-hab 的符号链接，两条路径是同一份已安装数据。代码不下载数据，
不使用 ReplicaCAD、uncluttered、articulated，也不编辑原生 HSSD 家具。

核心数据流
----------
1. hssd_preprocess.py 重新计算匹配 0.46 m 机器人尺寸的 NavMesh。
2. 按 NavMesh 高度把 island 归入物理 FloorSpec，但不把 island 当作房间。
3. 从官方 semantics/scenes/<id>.semantic_config.json 读取 region_annotations/poly_loop。
4. 每个导航采样点用多边形精确归属；多 region 重叠点和无归属点被丢弃。
   官方 polygon 是语义分区而不是墙体推断；开放式 kitchen/dining 可以是相邻或凹多边形。
   region-local BEV bounds 必须完整包含官方 polygon 和导航支撑，超出 rendered scene 的区域拒绝。
5. 构建 SceneSpec -> FloorSpec -> RegionSpec registry。
6. 对每个 region 检查面积、XZ 尺寸、障碍净空后三机器人成功率、局部 BEV 高度和渲染。
7. collection_specs() 产出强类型 (scene, floor, region) 目标。
8. collector.py 在同一 region 中采三台机器人和 2–4 个受控物体。
9. HabitatBackend 是唯一修改 Habitat 状态的层；它渲染三视角和 region-local BEV。
10. level2.py 从不可变 before state 产生同 region 的 counterfactual after state。
11. serialization.py 原子发布数据；validation.py 重载 registry/backend 做完整检查。

src/mri_dataset/config.py
-------------------------
CollectorConfig 定义唯一配置面。重要参数包括：
- 标准 HSSD scene config、官方 split、registry、NavMesh cache 和 object registry；
- 机器人直径/高度、固定 0.15 m 相机高度、0.235 m 前向偏移；
- region context 0.75 m、面积/尺寸/采样成功率阈值；
- 正式数据和 Pilot/Smoke 均使用 2048 视角与 0.00625 m/px BEV；Smoke 仅缩小场景和状态数量；
- resolution-aware benchmark visibility = max(绝对像素, 图像面积比例)；
- states_per_region 和 max_states_per_scene 的确定性平衡；
- 每类多 asset pool 与 asset SHA-256。

load_config() 会把人工批准 registry 物化成 canonical asset pool，加载 scene split，过滤
不合格 scene，并进行严格配置校验。generation_fingerprint() 包含协议配置、scene/split/object
registry hash 和机器人 mesh/material hash；运行参数中的 num_states/resume 不改变协议指纹。

src/mri_dataset/scene_registry.py
---------------------------------
RegionSpec 保存 region ID/category、floor、官方 polygon、相关 island、导航面积/边界、
带 context 的视觉 BEV 边界、局部 BEV 相机高度、资格/拒绝原因和预处理诊断。FloorSpec
拥有 regions；SceneSpec 拥有 floors、NavMesh/source hashes 与 preprocessing fingerprint。
旧 1.0 floor-only registry 会明确拒绝，不能静默作为正式协议加载。split manifest 始终按
scene ID；官方 train 确定性拆为 train/internal-val，官方 val 作为 test。

src/mri_dataset/regions.py
--------------------------
提供 HSSD poly_loop XZ 面积、含边界 point-in-polygon、唯一 region 归属和 BEV polygon
快速栅格化。region_mask 与 RGB/height/occupancy 使用完全相同的 BevMapping。

src/mri_dataset/hssd_preprocess.py
----------------------------------
- 从真实 HSSD inventory 发现 scene；不使用 apt 列表。
- NavMesh 参数包含静态物体，cache 保存 SHA-256。
- connected multilevel island 仍拒绝；不再因另一层 XZ 重叠而整体拒绝有效 region。
- region 三机器人成功率纳入正式障碍净空、距离和局部半径。
- 上行 ray 按 region 估计 overhead；安全时使用 nominal 2.2 m。
- 每个 scene 一次批量加载多个 BEV agent，生成 RGB/region-overlay/mask/occupancy/height 五联预览。
- get_topdown_island_view 的 int32 island map 用显式 eps 调用；-1 背景先过滤，
  再按 allowed island 生成严格 {0,1} occupancy，并注册到 Pathfinder 全局 bounds。
- preprocessing fingerprint 包含算法 schema、所有影响 floor/region/bounds/height/eligibility/
  sanity 的参数，以及 scene instance 和 semantic metadata SHA-256。

src/mri_dataset/sampling.py
----------------------------
机器人采样满足 navigable、floor Y、obstacle clearance、同 island、region polygon、局部
3.5 m、机器人间距。采样会更换 anchor，避免狭长区域中一次坏 anchor 造成假失败。yaw
模式 mixed 会选择 random 或 shared_focus；shared_focus 只表示朝共同焦点，不表示 region。

src/mri_dataset/habitat_backend.py
-----------------------------------
构造函数必须绑定 eligible scene/floor/region。它：
- 校验 NavMesh 设置、NavMesh SHA、approved asset 文件 SHA；
- 将 canonical 相对 ID 对 ObjectTemplateManager handle 做精确唯一解析，零/多匹配报错；
- 创建三组 pinhole RGB/depth/OBJECT_ID sensor 和一组 orthographic BEV sensor；
- 使用完成的落地 robot proxy，视觉 bottom 与 base/floor 一致；
- 生成 controlled category semantic 和 instance OBJECT_ID；原生背景 semantic=0；
- 保存官方 region mask、严格二值 occupancy、两者交集 navigable_region_mask 和 metric height；
- 用 Bullet contacts、downward rays、pinhole grid 和 orthographic rays 做几何验证；
- 记录机器人两两 Euclidean XZ 和 Pathfinder geodesic 距离；
- visibility 同时保存几何像素>0、像素数、面积比例和 benchmark gate。

src/mri_dataset/collector.py
-----------------------------
make_world_state() 生成 region-local factual state。所有机器人和物体必须显式通过
backend.point_in_region()。sample_object_choices() 对排序后的 category 和每类 asset 使用
state RNG，保证 category+variant 可复现；对象数量在 [2,4] 均匀确定采样。物体还必须
贴地、不碰撞、与机器人/物体分离。

输出层级为 scenes/<scene>/floors/<floor>/regions/<region>/states/<state>。更新索引时
区分 factual 与 intervention-derived state；最终严格禁止没有 edit 引用的 after-state。
Level-1 临时索引只为中断恢复允许“after 已原子发布、edit 尚未恢复”的短暂状态。

src/mri_dataset/interventions.py 与 level2.py
---------------------------------------------
支持 robot_translate、robot_rotate、object_translate、object_place_relative、object_remove。
所有平移/放置必须保持同 floor、同 region、navigable、collision-free。after 继承 before 的
region-local BEV frame，不重新居中。edit JSON 保存结构化米制参数、canonical instruction、
ID/OOD regime、before/after 可见视角数和 transition、BEV frame identical 标志。非 removal
编辑要求目标前后可见；object_remove 要求修改前可见、修改后 inactive 且不可见。中断后
可从 after state 的 intervention 重建确定性采样 slot/seed/edit JSON。

src/mri_dataset/world_state.py 与 state_io.py
----------------------------------------------
WorldState 保存 scene/floor/region、region category、bev_scope=semantic_region、context、
robots、objects、BEV、overlap、parent/edit、几何验证和机器人 pair distances。ObjectState
同时保存 runtime handle 和 portable canonical asset_identifier。state_io 对元数据无损重建。

src/mri_dataset/bev.py
----------------------
BevMapping 规定 u 向 +X、v 向 +Z，像素中心与 world bounds 注册。保留已验证的 Habitat
0.3.3 orthographic raw-depth 线性化。occupancy_from_pathfinder 将原生全局 NavMesh 栅格
重采样到任意 local BEV。annotate_bev 画机器人圆心、朝向和 FOV。

src/mri_dataset/serialization.py 与 visualization.py
-----------------------------------------------------
所有 state 先写同父目录临时文件，成功后 os.replace 原子发布。保存：
- BEV RGB、height、binary occupancy、region_mask、navigable_region_mask、semantic、instance；
- 三机器人 RGB、depth、semantic、instance；
- state/objects JSON、可视化 PNG、contact sheet。
contact sheet 顶部等宽显示带官方边界的 annotated RGB BEV、region mask、区域着色 occupancy、height；底部显示
R1/R2/R3 视角。Level-2 sheet 上下排列 before/after 和 instruction。

src/mri_dataset/validation.py
-----------------------------
验证 manifest/index/split、数组 dtype/shape/注册、相机内外参、depth/height ray、机器人
贴地、instance centroid、region membership、same-region Level-2 和 ID/OOD 参数域。full 模式
按 scene/floor/region 重用真实 HabitatBackend。

测试
----
tests 保留所有旧正确性测试，并新增 RegionSpec round-trip、duplicate/floor consistency、
point assignment、跨 region 近点、三机器人同 region、受控物体同 region、local bounds、
region mask、preprocess fingerprint、canonical 唯一解析、多 asset 确定性、decomposed 排除、
Level-2 region/BEV 一致和 resolution-aware visibility。真实环境测试实际加载 HSSD，渲染
semantic/instance/depth，并验证机器人贴地。

已知限制
--------
- 原生 HSSD 场景在当前标准 config 下没有 active SemanticScene labels；背景 semantic 为 0，
  房间监督来自官方 metadata 构建的 region_mask。
- 当前对象仅支持 floor support，不做桌面/receptacle placement。
- 主 benchmark 固定同一 object pool 做环境泛化；未实现 object-instance OOD track。
- 不把跨房间移动作为主任务；跨 doorway intervention 会被拒绝。
- 正式 2048/0.00625 存储成本较高，必须先阅读统计报告再启动完整 collection。
